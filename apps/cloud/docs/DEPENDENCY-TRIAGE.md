## Compatibility and verification impact

- xal-node was deliberately pinned from 1.1.6-beta2 to the published stable 1.1.4. This is a reviewed SDK change, not npm audit force. The compiled Msal code differs only in getStreamingTokens(), which this cloud-only client does not call. Used device-code, refresh, GSSV and cloud-offering methods are unchanged; shared HTTP, token models, TokenStore and lib exports are byte-identical. Generic Xal UUID generation differs, but this client uses Msal. Stable SDK uses uuid-1345 instead of uuid; the package allowlist was updated accordingly. Source comparisons are artifacts/auth-sdk-compare.diff and artifacts/auth-sdk-files-compare.log. Real sign-in remains a gate.
- The downloader change crosses @electron/get major versions after interface inspection: downloadArtifact, ElectronDownloadCacheMode, cache/mirror/checksum options and getProgressCallback remain supported. Version 5 uses FetchDownloader instead of got. A direct pinned development dependency plus matching override deduplicates both Electron and app-builder-lib onto 5.1.0; an earlier nested-only override did not reliably change the installed tree with the local npm resolver. Project already requires Node 24, above its >=22.12 engine requirement. Windows packaging and a fresh official checksum-file download validate this path; Mac packaging is still a gate. No security options were disabled.
- shell-quote remains pinned to 1.12.0 for the development runner. Electron remains 43.7.7. No blind force updates, credential access or security-setting changes were performed.
- Reproducible clean installation, formatter, TypeScript, 114 unit tests, 24 simulated Electron journeys, package inventory and no-network packaged SDK construction passed. Exact logs are listed in VALIDATION.md. The root audit gate remains enabled in CI.

## Release judgment
